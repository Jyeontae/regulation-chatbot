## 11-03 ~ 11-04 · 리랭커 설정 확정, 개선 후보 조사, 운영 전 정비

### 한 줄 요약
두 번째 검색어 세트로 리랭커 설정을 **후보 5개 + 다듬은 검색어 입력**으로 확정했고(Hit@1 0.76 → 0.89, 1세트), 개선 후보를 조사해 우선순위를 정한 뒤, **API 호출 없이** 외부 전송·기록·지연을 줄이는 운영 전 정비를 마쳤다.

### 1. 리랭커 설정 확정 (11-02 "진행 중" 마무리)
- 11-02에 검색어 1세트로만 본 결과가 우연인지 확인하려고, 다른 날 다듬은 **검색어 2세트**로 같은 비교를 다시 했다.
- 고르는 규칙은 결과를 보기 전에 정해 두었다: 리랭크 시간 예산(느린 10% 기준 5초) 안에서, 상위 4개 안에 정답이 드는 비율(Hit@4)을 떨어뜨리지 않는 설정 중 가장 좋은 것.

| 설정 | 1세트 Hit@1 / MRR | 2세트 Hit@1 / MRR | 규칙 판정 |
|---|---|---|---|
| 기준선 (리랭크 없음) | 0.76 / 0.86 | 0.73 / 0.84 | – |
| 후보 5개 + 원래 질문 | 0.80 / 0.90 | 0.82 / 0.91 | 통과 |
| **후보 5개 + 다듬은 검색어** | **0.89 / 0.93** | **0.82 / 0.91** | **통과 (채택)** |
| 후보 10개 + 다듬은 검색어 | 0.84 / 0.90 | 0.80 / 0.89 | Hit@4 하락 또는 시간 예산 초과 |

- 두 세트 모두 같은 설정이 뽑혔다. 리랭커 입력은 다듬은 검색어가 원래 질문과 **같거나 나았다**.
- 후보 10개는 가장 약한 "여러 조항" 질문의 Recall@4를 가장 많이 올렸지만(0.81~0.92), 규칙을 넘어 채택하지 않았다. 11-02 초안에서는 1세트 결과만 보고 "통과"로 적었는데, 규칙을 다시 대 보니 Hit@4가 1.00 → 0.98로 떨어져 탈락이었다. 리랭커가 빨라지면 다시 볼 후보로 남겼다.
- **적용:** 채팅 화면과 답변 평가가 같은 방식(다듬은 검색어로 리랭크)을 쓰도록 맞췄다.

### 2. 개선 후보 조사
- 예제 노트북·강의 자료, 지금까지의 작업 문서, 최신 자료(검색·LLM·평가·업무 기능)를 나눠 조사하고, 나온 사실 주장 101개를 하나씩 교차 검증했다(확인 78, 일부 확인 19, 확인 불가 3, 반박 1).
- 결과를 권고 16개와 "하지 않는 것이 좋은 것" 16개로 정리했다. 예: 점수 문턱으로 미리 거절하기(근거 데이터 부족), LLM으로 순위 매기기·압축(규정 본문이 외부로 더 나감), 다른 공급자로 자동 전환(사용자가 고르지 않은 곳으로 전송됨).
- 가장 큰 약점은 **여러 조항 질문**(검색 Recall@4 0.65~0.69)이고, 원인에 따라 처방이 갈리도록(중복 제거 / 질문 분해 / 참조 조문 따라가기 / 리랭커 교체) 진단 순서를 정했다.
- 검증에서 바로잡힌 것도 기록했다. 예: "리랭커 입력을 다듬은 검색어로 잰 값이 지금 챗봇의 값"이라는 전제는 틀렸다. 당시 챗봇은 원래 질문을 넣고 있었다. 이 차이가 1절의 적용 작업으로 이어졌다.

### 3. 운영 전 정비 (API 호출 없음)
조사 결과 중 한 시간 안에 끝나고 외부 호출이 필요 없는 항목을 먼저 반영했다.

| 정비 | 이유 |
|---|---|
| OpenAI 호출에 저장 끄기(`store=False`) 명시 | 공식 문서의 기본값 설명이 서로 달라 코드에서 고정. 보내는 내용은 같고 보관만 줄인다 |
| 질문 300자 상한 | 긴 문서를 붙여 넣으면 그 전문이 다듬기·답변 두 번 외부로 나간다. 넘으면 LLM을 부르지 않는다 |
| 검색어 다듬기 5초 제한 | 응답이 늦으면 재시도 없이 원래 질문으로 검색. 평가 스크립트에는 걸지 않아 평가가 조용히 흔들리지 않게 했다 |
| 채팅 기록 끄기 | 설치된 Gradio는 실행 기록이 기본으로 켜져 있고 외부 저장소로 보내는 기능도 있다. flag·실행 기록·브라우저 대화 저장을 모두 끄고 `.gradio/`를 git 제외 |
| 모델 오프라인 실행 | 채팅 중에는 Hugging Face에 접속하지 않고 받아 둔 모델만 쓴다. 라이브러리가 import 시점에 설정을 읽어 `.env`가 아니라 실행 스크립트 맨 앞에서 지정 |
| effort 설정 정리 | 코드에 고정돼 있던 다듬기 effort를 설정으로 빼고, 모델이 받는 값 목록에 맞게 변환 규칙을 고쳤다 |

- 확인: 컴파일, 설정 로드, OpenAI 요청 본문(전송 없이 로컬에서 생성), 오프라인 모델 로드까지 확인했다.

### 4. 결정: 재평가 없이 마무리

- 공급자를 바꿀 때마다 전체 평가를 다시 돌리면 결정이 끝나지 않는다. **기존 Claude 평가 결과를 근거로 설정을 확정**하고, OpenAI 기준 재평가는 하지 않기로 했다.
- 대신 이 한계를 문서와 README에 그대로 적었다(리랭커 수치는 Claude Haiku가 다듬은 검색어 기준).
