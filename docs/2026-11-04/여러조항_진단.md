# 여러 조항 진단 (2026-11-04, 2차 시작)

> 2차 첫 작업. 11-03 개선 조사 3절 "빠른 실행 5"(여러 조항 진단 집계)를 실행했다.
> 저장된 검색어(10-30 Haiku 다듬기, 1·2세트)를 재사용해 **API 호출 없이** 로컬에서 쟀다. 화면 출력과 이 문서에는 숫자와 질문 id만 있다.
> 도구: `scripts/diagnose_multi.py` (챗봇과 같은 검색: 원래 질문 + 다듬은 검색어 합치기 → 후보 5개를 다듬은 검색어로 리랭크 → 상위 4개)

## 0. 결론

| 질문 | 답 |
|---|---|
| 정답 조문을 **검색이 아예 못 찾나?** | **아니다.** 합친 검색 상위 20개 안에 정답이 다 있다 (여러 조항 Recall 1.00, 두 세트) |
| **중복**이 4칸을 차지하나? | **아니다.** 같은 조문 조각 0칸, 다른 규정에 실린 같은 본문 0칸 (76칸 중) → C1 중복 제거는 효과 없음 |
| **참조**를 따라가면 닿나? | **거의 아니다.** 상위 2개 조문의 참조로 닿는 놓친 정답은 0/7, 1/10 → C4 참조 따라가기는 효과 작음 |
| 그럼 왜 놓치나? | 놓친 정답 대부분이 **6~11위**에 있다. 리랭크 후보(5개) 바로 밖이다 |
| 특징 | 놓친 정답의 대부분(6/7, 8/10)이 **이미 상위 4칸에 들어온 규정의 다른 조문**이다 |
| 특징 | 일부는 **원래 질문 목록에서는 1~2위**인데 합친 순위에서 9~11위로 밀린다 (Q35). 다듬은 검색어 쪽 유사도가 대체로 높아, 최대값으로 합치면 원래 질문이 찾은 조문이 밀린다 |

→ 원인은 "못 찾음"이 아니라 **"찾았는데 5위 안에 못 듦"**이다. 처방 후보는 **C2 검색어별 몫으로 후보 모으기**와 **리랭크 후보 늘리기**이다(가능하면 C5 리랭커 가속과 함께).

## 1. 지표 (여러 조항 유형 8문항, 정답 조문 22개)

| 지표 | 1세트 | 2세트 |
|---|---:|---:|
| Recall@4 리랭크 전 | 0.69 | 0.69 |
| **Recall@4 리랭크 후 (지금 챗봇)** | **0.76** | **0.69** |
| Recall 리랭크 후보 5개 | 0.76 | 0.72 |
| Recall 합친 검색 20개 | **1.00** | **1.00** |
| 같은 조문 조각 / 같은 본문 (32칸 중) | 0 / 0 | 0 / 0 |
| 상위 4칸 종류 | 본문 27, 별표·별지 5 | 본문 28, 별표·별지 4 |

11-03 문서 1절의 "후보 5 + 다듬은 검색어" 여러 조항 Recall@4(0.76 / 0.69)와 같아 재현이 확인됐다.

정답이 2개 이상인 질문 전체(19문항, 정답 조문 46개)로 넓혀도 같은 모습이다: Recall@4 0.85 / 0.79, 합친 검색 20개 1.00 / 0.97, 중복 0.

## 2. 놓친 정답의 원인

| 원인 | 1세트 (여러 조항 / 전체) | 2세트 (여러 조항 / 전체) | 처방 |
|---|---:|---:|---|
| 순위 밀림 (후보 5개 안인데 리랭크 뒤 4위 밖) | 0 / 1 | 1 / 3 | C5 리랭커 |
| **후보 밖 (6~20위)** | **5 / 6** | **6 / 6** | C2 몫 방식, 후보 늘리기, C3 질문 분해 |
| 검색 밖 (20위 밖) | 0 / 0 | 0 / 1 | C4, C3 |

- 놓친 정답의 합친 검색 순위: 1세트 [5, 6, 6, 8, 9, 11, 16], 2세트 [4, 5, 5, 6, 7, 8, 9, 11, 11]. 대부분 **11위 안**이다.
- 놓친 정답을 더 높게 찾은 쪽: 1세트 다듬은 검색어 4·원래 질문 3, 2세트 **원래 질문 7**·다듬은 검색어 3. 다듬기 결과에 따라 어느 쪽이 찾을지가 흔들린다.
- 종류: 본문이 대부분, 별표·별지 2~3개.

- **Q35가 C2의 전형이다.** 원래 질문으로는 정답이 1·2위인데, 다듬은 검색어 쪽 결과가 유사도가 높아 합친 순위에서 9~11위로 밀린다. 원래 질문과 다듬은 검색어에서 각각 상위 몇 개씩 가져오면(C2) 후보에 들어온다.
- Q31·Q33·Q38은 두 목록 모두에서 6~13위라 C2로는 안 되고 후보를 10개 안팎으로 늘려야 닿는다.

## 4. 처방 판단

| 처방 | 판단 | 근거 |
|---|---|---|
| C1 중복 제거 | **안 함** | 중복 0칸 |
| C4 참조 따라가기 | **보류** | 참조로 닿는 놓친 정답 0~1개 |
| **C2 검색어별 몫** | **1순위 후보** | Q35처럼 한쪽 목록 상위가 합치기에서 밀리는 경우를 직접 고친다. 로컬, 결과가 매번 같고, 조정값 하나 |
| **리랭크 후보 늘리기 (+ C5 가속)** | **2순위 후보** | 놓친 정답 대부분이 11위 안. 11-03에 후보 10개 + 다듬은 검색어가 여러 조항 Recall@4 0.92 / 0.81이었지만, 리랭크 시간이 예산(p90 5초)을 넘거나 Hit@4가 1.00 → 0.98로 떨어졌다. 리랭커가 빨라지면 다시 볼 수 있다 |
| C3 질문 분해 | 나중 | 다듬기 출력이 바뀌어 효과를 보려면 API 호출이 필요하다 |

## 5. 다음 단계 (제안)

C2(몫 방식)와 후보 수(5·8·10)를 조합해 **저장된 검색어로 로컬 검색 비교**를 한다. API 호출은 없다. 판정 규칙은 결과를 보기 전에 정한다.
