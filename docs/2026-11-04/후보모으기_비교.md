# 리랭크 후보 모으기 비교 (2026-11-04)

> [여러조항_진단](여러조항_진단.md)의 처방 후보 두 가지(C2 검색어별 몫, 후보 수 늘리기)를 저장된 검색어로 로컬 비교한다. API 호출은 없다.
> **1절의 규칙은 실행 전에 적었다.** 결과는 2절부터.

---

## 1. 비교 설정과 판정 규칙 (실행 전 기록)

### 설정

| 이름 | 리랭크 후보 모으는 방법 | 후보 수 |
|---|---|---|
| **max5 (지금)** | 원래 질문·다듬은 검색어 결과를 청크별 높은 유사도로 합쳐 상위 5개 | 5 |
| max8 | 같은 방식, 상위 8개 | 8 |
| max10 | 같은 방식, 상위 10개 | 10 |
| quota3 | 원래 질문 상위 3개 + 다듬은 검색어 상위 3개 (겹치면 하나) | 최대 6 |
| quota4 | 각각 상위 4개 | 최대 8 |
| quota5 | 각각 상위 5개 | 최대 10 |

모든 설정이 후보를 **다듬은 검색어**로 리랭크해 상위 4개를 답변에 넘긴다(지금 챗봇과 같음). 검색어는 10-30 저장분 1·2세트.

### 판정 규칙
- **주지표:** 여러 조항 유형(8문항) Recall@4. 지금(max5)보다 **두 세트 모두** 올라야 한다.
- **지킴선 (정답 있는 45문항, 지금 대비):** Hit@4 하락 없음, Hit@1·MRR 하락 0.05 이내, 리랭크 시간 p90 5초 이내 (두 세트 모두).
- **선택:** 통과한 설정 중 두 세트 평균 여러 조항 Recall@4가 가장 높은 것. 같으면 후보가 적은(빠른) 쪽.
- 통과한 설정이 없으면 지금(max5)을 유지하고 C5(리랭커 가속)로 넘어간다.
- 리랭크 시간은 쌍마다 따로 잰 값의 합이다(지금 코드도 한 쌍씩 실행). 같은 청크는 한 번만 재서 설정끼리 같은 측정값을 쓴다.

## 2. 결과 (정답 있는 45문항, 여러 조항 8문항)

리랭크 시간은 평균 / p90. 측정 중 채팅 서버(10:10 실행)가 켜져 있었지만 쓰지 않았다.

|---|---|---|---|---|---|---:|---|
| max5 (지금) | 0.76 / 0.69 | 0.85 / 0.79 | 0.89 / 0.82 | 1.00 / 1.00 | 0.93 / 0.91 | 5.0 | 1.9/2.7 · 2.2/3.0초 |
| **max8** | **0.90 / 0.81** | **0.88 / 0.84** | 0.87 / 0.82 | 1.00 / 1.00 | 0.92 / 0.90 | 8.0 | 3.0/3.9 · 3.5/4.4초 |
| max10 | 0.92 / 0.81 | 0.89 / 0.84 | 0.84 / 0.80 | **0.98** / 1.00 | 0.90 / 0.89 | 10.0 | 3.7/4.9 · 4.2/**5.2**초 |

| **max8** | 통과 | 통과 | **채택** (두 세트 평균 여러 조항 R@4 0.855, 통과 설정 중 최고) |
| max10 | 탈락 (Hit@4) | 탈락 (p90 5.2초) | – |

| quota4 | 통과 | 통과 | 평균 0.80 |

## 3. 적용

- `.env`의 `RERANK_CANDIDATES`를 **5 → 8**로 바꿨다. 코드 변경 없음(채팅·답변 평가가 이 값을 쓴다).
- 비용: 리랭크 시간이 질문당 평균 약 +1.2초(p90 2.7~3.0 → 3.9~4.4초). 예산 5초 안이다. 외부 전송은 그대로다(LLM에는 여전히 상위 4개).
- 지킴선: Hit@1은 1세트에서 0.02 내렸고(0.89 → 0.87, 1문항) 2세트는 같다. MRR은 0.01 내렸다.

## 4. 관찰과 한계

- **quota(몫)는 Q35를 고치지만 Q33·Q38은 못 고친다.** max8은 반대다(2세트 Q35는 1/3 그대로). 두 방식을 합치면(max8 ∪ quota) 더 나을 수 있지만, 결과를 보고 새 설정을 만드는 것은 과적합 위험이 있어 이번에는 하지 않는다. 다음 비교 때 미리 후보로 적고 잰다.
- Q31(2/3)·Q37(2세트 2/4)은 어느 설정으로도 다 찾지 못한다. 질문 분해(C3) 후보다.
- 여러 조항 문항이 8개뿐이다(문항 하나가 정답 2~4개). 보류셋으로 확인하지 못했다.
- 검색어는 10-30 Haiku 다듬기 세트다. 지금 챗봇은 gpt-5.4-mini가 다듬는다(11-04 원칙에 따라 재측정하지 않음).
- 실제 채팅에서 체감 시간 확인은 사용자 몫이다. **10:10에 띄운 채팅 서버는 오늘 바뀐 코드·설정 이전 상태이므로 다시 실행해야 한다.**
