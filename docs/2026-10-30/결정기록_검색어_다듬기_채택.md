# 기술 의사결정: 하이브리드 검색을 버리고 검색어 다듬기(M4b)를 채택한 이유

| 항목 | 내용 |
|---|---|
| 프로젝트 | 사내 규정 RAG 챗봇 |
| 결정일 | 2026-10-30 |
| 결정 | 챗봇 검색을 "벡터 검색"에서 "검색어 다듬기 + 원래 질문 합치기(M4b)"로 바꾼다. 하이브리드 검색(BM25 + RRF)은 채택하지 않는다 |
| 결정자 | 본인 |
| 근거 자료 | [채팅화면과_검색튜닝_실험기록](채팅화면과_검색튜닝_실험기록.md), [검색_튜닝_실험기록](../2026-10-29/검색_튜닝_실험기록.md) (실험 규칙·기준선 v0) |

이 문서에는 집계 점수와 질문 id만 적는다. 질문·정답·규정명은 `data/eval/`(git 제외)에만 둔다.

## 1. 배경

### 측정 조건

| 항목 | 값 |
|---|---|
| 평가셋 | 50문항 (정답 있음 45 / 규정에 없음 5), 지문 `da8ccbe8506a` |
| 유형 | 단순 사실 20, 조건 판단 10, 여러 조항 8, 구어체 7 |
| 청크 | 1,003개 (별첨 인식 반영, 지문 `d9657b04ff30`) |
| 임베딩·저장소 | `BAAI/bge-m3` (CPU), Chroma cosine |
| LLM에 넘기는 청크 | 4개 (`RETRIEVER_K=4`) → 핵심 지표는 Hit@4 |
| 문항 하나의 무게 | 전체 1문항 ≈ 0.02, 조건 판단 1문항 = 0.10, 구어체 1문항 ≈ 0.14 |
| 차이로 보는 기준 | 0.05 이상 (실험 규칙) |

### 출발점: v1 (벡터 검색)

| 지표 | 값 |
|---|---|
| Hit@1 | 0.69 (45문항 중 31개) |
| **Hit@4** | **0.96 (43개)** |
| Recall@4 | 0.87 |
| MRR@10 | 0.80 |

| 유형 (k = 4) | 질문 | Hit@4 | Recall@4 | MRR |
|---|---:|---:|---:|---:|
| 단순 사실 | 20 | 1.00 | 0.97 | 0.89 |
| 조건 판단 | 10 | 1.00 | 1.00 | 0.62 |
| 여러 조항 | 8 | 1.00 | 0.73 | 0.94 |
| **구어체** | 7 | **0.71** | **0.57** | **0.63** |

**구어체가 가장 약하다.** 7문항 중 2문항(Q40 6위, Q43 상위 10개 밖)의 정답이 LLM에 전달되지 않는다.

### 문제를 드러낸 질문

채팅 화면에서 금액을 묻는 구어체 질문 하나가 다른 카테고리 규정만 답했다. 별첨 인식(D7)을 고친 뒤에도 정답 별첨은 LLM에 전달되지 않았다.

| 같은 질문을 | 정답 별첨 순위 | 정답 유사도 | 1위 유사도 |
|---|---:|---:|---:|
| 사용자가 쓴 구어체 그대로 검색 | **7위** (LLM에 안 감) | 0.548 | 0.665 |
| 규정 용어로 바꿔 써서 검색 | **3위** | 0.708 | 0.744 |

- 구어체 그대로 검색하면 상위 10개 중 6개가, 금액 표가 많은 다른 규정(파일 2개)의 청크였다. 금액을 묻는 표현이 금액 표를 끌어왔다.
- **같은 뜻이어도 말투에 따라 정답 순위가 7위와 3위로 갈린다.** 이것을 해결할 문제로 정했다.

## 2. 검토한 선택지

| 선택지 | 내용 | 기대 효과 | 추가 비용 | 실험 |
|---|---|---|---|---|
| A. 하이브리드 검색 (M3) | 벡터 검색 + Kiwi 형태소 BM25를 RRF로 합침 | 표처럼 단어만 있는 청크, 정확한 용어 질문 보완 | 없음 (LLM 호출 없음) | 함 |
| B. 검색어 다듬기 (M4) | LLM이 질문을 규정 말투 검색어 한 줄로 바꿔 그것으로 검색 | 구어체 보완 | 질문당 LLM 1회 | 함 |
| C. B + 원래 질문 합치기 (M4b) | 원래 질문과 다듬은 검색어로 각각 검색해 청크마다 높은 유사도를 씀 | B의 이득 + 원래 질문이 잘 찾던 것 유지 | 질문당 LLM 1회 + 검색 1회 | 함 |
| D. k 늘리기 (4 → 8) | LLM에 더 많이 넘김 | 단순함 | 외부로 보내는 규정 본문·토큰 2배, 엉뚱한 발췌가 섞임 | 검토만 |
| E. 구어체 용어 사전 (M2) | 일상어 → 규정 용어 사전으로 질문 보완 | 비용·지연 없음 | 사전을 사람이 계속 채워야 함 | 보류 |

## 3. 판단 기준

1. **Hit@4** — LLM에 넘기는 4개 안에 정답이 드는가 (실험 규칙의 1순위 지표)
2. **잃지 않을 것** — 기존에 잘 되던 유형(조건 판단·여러 조항)이 떨어지지 않는가
3. **구어체 개선** — 구어체 Hit@4·MRR이 오르는가
4. **비용·지연·외부 전송** — 질문마다 늘어나는 호출과 보내는 내용
5. **재현성** — LLM이 끼면 실행마다 결과가 흔들리므로 2회 이상 재고, 비교는 같은 입력으로 한다

## 4. 실험 결과

### 4.1 A. 하이브리드 검색 (M3) → 미채택

**시도한 이유:** 정답 별첨은 표라서 문장 뜻은 약하지만 핵심 단어는 그대로 들어 있다. 단어 일치 검색(BM25)을 더하면 이런 청크가 올라올 것으로 봤다. LLM 호출이 없어 추가 비용이 0이고, 실험 후보 목록에 있던 항목이다. 미리 세운 가설은 "단순 사실 MRR이 오른다"였다.

조건: Kiwi 0.24.1 내용 형태소(NNG·NNP·NNB·NR·SN·SL·SH·XR·VV·VA), `BM25Okapi` 기본값, RRF 상수 60, 두 검색 같은 가중치, 각 상위 30개 후보.

| 지표 | v1 | M3 | 변화 |
|---|---:|---:|---:|
| Hit@1 | 0.69 (31) | 0.64 (29) | −0.05 |
| **Hit@4** | **0.96 (43)** | **0.89 (40)** | **−0.07** |
| Recall@4 | 0.87 | 0.80 | −0.07 |
| MRR@10 | 0.80 | 0.77 | −0.03 |
| 단순 사실 MRR | 0.89 | **0.94** | **+0.05 (가설 적중)** |
| 조건 판단 Hit@4 | 1.00 (10/10) | 0.80 (8/10) | −0.20 |
| 여러 조항 MRR | 0.94 | 0.88 | −0.06 |
| **구어체 Hit@4** | 0.71 (5/7) | **0.57 (4/7)** | **−0.14** |
| 구어체 MRR | 0.63 | 0.36 | −0.27 |
| 문제 질문의 정답 순위 | 7위 | 3위 | 개선 |

- 정답 순위가 오른 질문 6개(Q02·Q09·Q21·Q26·Q27·Q40), 내린 질문 8개(Q12·Q25·Q28·Q32·Q39·Q41·Q42·Q44)다. 벡터 1위였던 Q25는 상위 10개 밖으로, Q44는 6위로 밀렸다.
- **판단:** 가설(단순 사실 MRR)은 맞았지만 1순위 지표 Hit@4가 0.05 넘게 떨어졌고, 해결하려던 구어체가 오히려 나빠졌다. 채팅 화면에서 직접 비교한 결과도 같았다.
- **원인:** RRF는 두 목록에 모두 든 청크를 크게 우대한다. 벡터 1위라도 BM25 후보에 없으면 1/61 ≈ 0.016점이다. 반면 두 목록에서 각각 10위인 청크는 2/70 ≈ 0.029점을 받아 앞선다. 구어체의 일상어는 규정 용어와 단어가 달라 BM25가 엉뚱한 청크를 고르고, 그 청크가 RRF로 올라왔다 (추정).
- **교훈:** 문제를 발견한 질문 하나는 7위 → 3위로 좋아졌지만 전체는 나빠졌다. 질문 하나로 판단하지 않는다.

### 4.2 B. 검색어 다듬기 (M4) → 단독으로는 미채택

**시도한 이유:** 하이브리드로 구어체가 더 나빠졌다(0.71 → 0.57). 문제는 "단어"가 아니라 **"말투"**다. 규정 용어로 손수 바꿔 쓰면 7위 → 3위가 되는 것을 이미 확인했으므로, 그 바꾸는 일을 LLM에 맡긴다.

조건: `claude-haiku-5-5`, effort `low`, 질문당 약 1초(측정 1.0~1.3초), 질문만 전송(규정 본문 없음). 프롬프트에는 예시를 넣지 않았다. 평가셋에 자주 나오는 일상어를 예시로 넣으면 평가셋에 맞춘 프롬프트가 되기 때문이다. LLM 출력이 실행마다 달라 2회 쟀다.

| 지표 | v1 | M4 (1회 / 2회) | 변화 |
|---|---:|---:|---:|
| Hit@1 | 0.69 (31) | 0.76 (34) / 0.73 (33) | +0.04~0.07 |
| **Hit@4** | **0.96 (43)** | **0.93 (42) / 0.96 (43)** | **변화 없음** |
| Recall@4 | 0.87 | 0.84 / 0.85 | −0.02~0.03 |
| MRR@10 | 0.80 | 0.84 / 0.82 | +0.02~0.04 |
| **구어체 Hit@4** | 0.71 (5/7) | **0.86 (6/7) / 1.00 (7/7)** | **+0.15~0.29** |
| 구어체 MRR | 0.63 | 0.79 / 0.82 | +0.16~0.19 |
| **조건 판단 Hit@4** | 1.00 (10/10) | **0.80 (8/10) / 0.80 (8/10)** | **−0.20 (두 번 모두)** |
| 여러 조항 Recall@4 | 0.73 | 0.64 / 0.60 | −0.09~0.13 |
| 문제 질문의 정답 순위 | 7위 | 3위 | 개선 |

- **얻은 것:** v0부터 못 찾던 Q43이 1위, Q40이 6위 → 1위. Q22·Q26·Q27·Q37도 1위로 올랐다.
- **잃은 것:** Q21(3 → 5·6위), Q23(2 → 4위), Q25(1 → 6·5위), Q35(1 → 3·4위), Q39(1 → 2위). 질문을 검색어 한 줄로 줄이면서 조건이나 둘째 주제가 빠진 것으로 보인다 (추정).
- **흔들림:** 같은 설정인데 Q05(1위 / 4위), Q41(상위 10개 밖 / 4위)이 실행마다 달랐다.
- **판단:** 구어체 개선은 분명하다. 하지만 1순위 지표 Hit@4가 오르지 않았고, 조건 판단 하락이 두 번 모두 나타났다.

### 4.3 C. 원래 질문 합치기 (M4b) → 채택

**시도한 이유:** M4에서 밀린 Q21·Q23·Q25는 원래 질문으로 검색하면 1~3위였던 문항이다. 원래 질문 검색도 함께 쓰면 이 문항들을 지키면서 다듬기의 이득을 얻을 수 있다. 두 검색 모두 같은 임베딩·같은 코사인 척도라 점수를 그대로 비교할 수 있다. 그래서 순위로 합치는 RRF(M3의 실패 원인) 대신 **청크마다 높은 유사도**를 쓴다.

**공정한 비교:** M4 두 실행에서 저장한 다듬은 검색어를 그대로 재사용했다(`--rewrite-from`). 검색어는 같고 합치는 방식만 다른 짝지은 비교이며, API를 다시 부르지 않았다. 재사용이 제대로 되는지는 v1과 M4 1회를 다시 채점해 기록된 점수와 똑같이 나오는 것으로 확인했다.

| 지표 | v1 | M4 (1회 / 2회) | **M4b (1회 / 2회 검색어)** |
|---|---:|---:|---:|
| Hit@1 | 0.69 (31) | 0.76 / 0.73 | 0.76 (34) / 0.73 (33) |
| Hit@3 | 0.91 | 0.91 / 0.87 | 0.98 / 0.93 |
| **Hit@4** | **0.96 (43)** | 0.93 / 0.96 | **1.00 (45) / 0.98 (44)** |
| Recall@4 | 0.87 | 0.84 / 0.85 | **0.91 / 0.90** |
| MRR@10 | 0.80 | 0.84 / 0.82 | **0.86 / 0.84** |

| 유형 (k = 4) | v1 Hit@4 / MRR | M4 Hit@4 / MRR | M4b Hit@4 / MRR |
|---|---|---|---|
| 단순 사실 | 1.00 / 0.89 | 1.00 / 0.85~0.89 | 1.00 / 0.85~0.89 |
| 조건 판단 | 1.00 / 0.62 | 0.80 / 0.69 | **1.00 / 0.82** |
| 여러 조항 | 1.00 / 0.94 | 1.00 / 0.91~0.92 | 1.00 / 0.84~0.85 |
| 구어체 | 0.71 / 0.63 | 0.86~1.00 / 0.79~0.82 | **0.86~1.00 / 0.81~0.82** |

정답 순위 (v1 → M4 1회·2회 → M4b 1회·2회 검색어)

| 구분 | 질문 |
|---|---|
| M4의 이득을 지킴 | Q22 2→1·1→1·1, Q26 4→1·1→1·1, Q27 3→1·1→1·1, Q40 6→1·1→1·1, Q43 없음→1·1→1·1 |
| M4의 손실을 되찾음 | Q21 3→5·6→3·3, Q23 2→4·4→2·2, Q25 1→6·5→1·1 |
| M4의 이득이 v1 순위로 돌아감 | Q37 2→1·1→2·2 |
| 남은 손실 | Q35 1→3·4→3·4, Q39 1→2·2→2·2 |
| 2회 검색어에서만 손실 | Q05 1→1·4→1·4, Q41 4→없음·4→4·5 |

- **판단:** v1보다 낮아진 전체 지표가 처음으로 하나도 없다. 두 검색어 세트에서 방향이 같다. 조건 판단은 v1 수준(10/10)을 지키면서 MRR이 0.62 → 0.82로 올랐다. 문제 질문의 정답은 3위로 LLM에 전달된다.
- **크기:** Hit@4 +0.02~0.04는 0.05 기준보다 작다. 다만 v1이 이미 43/45여서 오를 수 있는 폭이 최대 0.04였다. 그래서 판단은 정답이 4위 밖인 문항 수(v1 2개 → M4b 0~1개)와 유형별 변화로 보충했다.

## 6. 포기한 것과 대응 (트레이드오프)

| 포기한 것 | 대응 |
|---|---|
| 질문당 지연 약 1초, LLM 호출 1회 추가 | 작은 모델(Haiku)과 effort `low`로 줄인다. 다듬기가 실패하면 원래 질문으로 검색해 답변은 계속 나간다 |
| 외부 전송 1회 추가 (질문 텍스트) | 다듬기에는 질문만 보낸다. 규정 본문은 원래대로 답변 단계에서만 나간다 |
| 결과의 재현성 (실행마다 1~2문항이 달라짐) | 실험 도구(`search.py`·`eval_retrieval.py`)의 기본값은 v1로 둔다. 비교 실험은 `--rewrite-from`으로 같은 검색어를 재사용한다 |
| Q35·Q39, 여러 조항 MRR(0.94 → 0.84~0.85) | 다듬은 검색어 쪽 유사도가 전반적으로 높다(1등 유사도 평균 0.682 → 0.711~0.712). 그래서 원래 질문의 정답 점수를 덮는 경우가 있다. 합칠 때의 점수 보정을 다음 후보로 둔다 |
| 하이브리드의 단순 사실 MRR 개선(+0.05) | 코드는 남겨 두고(`RETRIEVER_MODE=hybrid`) 기본값으로 쓰지 않는다. BM25 비중을 낮춘 결합(M3a·M3b)은 후보로 남긴다 |

## 7. 한계와 다시 검토할 조건

### 한계

- **보류셋으로 확인하지 못했다.** 보류셋 20문항의 정답 칸이 아직 `확인필요`다. 평가셋 결과만으로 채택했다 (실험 규칙의 예외, 본인 결정).
- **표본이 작다.** 구어체는 7문항이라 1문항 차이가 0.14다.
- **검색 지표만 쟀다.** 답변 품질(정확성·근거 인용)은 아직 평가하지 않았다.
- **기준선 v1에는 두 변화가 섞여 있다.** v1은 별첨 인식(D7)과 평가셋 정답 4개 수정이 함께 들어간 결과라, v0 → v1 개선을 하나의 원인으로 설명할 수 없다.

### 다시 검토할 조건

- 보류셋 정답을 채운 뒤 v1과 M4b를 재서 **M4b가 v1보다 나쁘면** → `chat.py --no-rewrite`로 되돌린다.
- 답변 평가에서 **다듬기가 답변 품질이나 근거 인용을 해치면** → 재검토한다.
- **질문당 1초 지연이 사용 경험에 문제**가 되면 → 같은 질문의 검색어 캐시나 용어 사전(E)으로 대체를 검토한다.
- **여러 조항 손실이 답변 누락으로 이어지면** → 합칠 때 다듬은 검색어 점수를 보정하는 실험을 한다.

## 8. 이 결정으로 바뀐 것

| 구분 | 변경 전 | 변경 후 |
|---|---|---|
| 챗봇 검색 | 원래 질문으로 벡터 검색 | 다듬은 검색어 + 원래 질문으로 각각 검색해 높은 유사도로 합침 (`--no-rewrite`로 끔) |
| 질문당 LLM 호출 | 1회 (답변) | 2회 (다듬기 `claude-haiku-5-5` + 답변) |
| 외부 전송 | 질문 + 상위 4개 청크 (답변) | 위와 같고, 다듬기에 질문을 한 번 더 보냄 |
| 채팅 화면 | 답변 | 답변 맨 위에 다듬은 검색어 표시 |
| 실험 도구 기본값 | v1 | v1 그대로 (`--rewrite --merge-original`로 M4b) |
| 평가 방법 | 실행마다 LLM으로 다듬기 | `--rewrite-from`으로 저장한 검색어 재사용 (짝지은 비교) |
| 하이브리드 검색 | 없음 | 옵션으로 남김 (`RETRIEVER_MODE=hybrid`, 기본값 아님) |
