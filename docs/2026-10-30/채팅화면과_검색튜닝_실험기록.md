## 2. D7 별첨 인식 → 기준선 v1

### 발견

채팅 화면에서 구어체 질문 하나가 다른 카테고리 문서만 찾았다. 정답 규정에는 chunk_id가 `#별첨N`인 청크가 하나도 없었다. 분할의 첨부 제목 패턴(`APPENDIX`)이 `별표`·`별지`만 인식해서, `[별첨 N]` 줄이 제목으로 잡히지 않고 앞 부칙·조 청크 뒤에 붙어 있었다.

| id | 바꾸는 것 | 가설 | 볼 지표 |
|---|---|---|---|
| D7 | 별첨 인식 | `[별첨 N]`이 앞 부칙·조 청크에 붙어 있어 별첨 내용을 못 찾는다 | 개선할 질문 |

### 변경

- 첨부 제목·참조 패턴에 `별첨`을 추가했다. 긴 별첨은 별표처럼 줄 경계에서 자른다.
- 분할 결과: 청크 1,000개 → 1,003개. 별첨 7개(사규 2개 문서, 지침 1개 문서)가 생기고 부칙은 75개 → 71개.

### 평가셋 수정

- 정답이 `#부칙1`로 적힌 4문항(Q03, Q04, Q27, Q32)은 실제 근거가 그 부칙 뒤에 붙어 있던 별첨이었다.
- 기대 답과 후보 청크(부칙1, 별첨1~3)의 임베딩 유사도로 대응을 정했다. 4문항 모두 별첨3이 약 0.73, 나머지는 0.49 이하라서 `#별첨3`으로 바꿨다. 본문은 출력하지 않고 점수만 봤다.
- 지문 `a6644be4bc3c` → `da8ccbe8506a`. 수정 전 파일은 `data/eval/eval_set.bak-20261030.md`.

### 규칙 예외

분할과 평가셋을 함께 바꿨다. v0 청크에는 `#별첨3`이 없어서, 새 평가셋으로 v0을 다시 채점하면 이 4문항이 `[제외]`된다. 두 변화의 효과를 가를 수 없으므로 이 결과를 **새 기준선 v1**로 삼고, 이후 실험은 v1과 비교한다.

### 해석

1. **가설은 맞았지만 채택하지 않는다.** 단순 사실 MRR이 0.89 → 0.94로 올랐다. 하지만 Hit@4가 0.96 → 0.89로 떨어졌다. 기본값은 `vector`로 둔다.
2. **RRF는 두 목록에 모두 든 청크를 크게 우대한다.** 벡터 1위라도 BM25 후보 30개 안에 없으면 점수가 1/61 ≈ 0.016이다. 두 목록에서 10위씩인 청크는 2/70 ≈ 0.029라 앞선다. 벡터 1위였던 Q25·Q44·Q39가 밀린 것이 이 경우로 보인다 (추정, 질문별 BM25 순위는 아직 확인하지 않음).
3. **구어체가 가장 많이 떨어졌다** (Hit@4 0.71 → 0.57, MRR 0.63 → 0.36). 일상어는 규정 용어와 단어가 달라 BM25가 엉뚱한 청크를 고르고, 그 청크가 RRF로 올라온다 (추정).
4. **질문 하나로 판단하면 안 된다.** D7을 발견한 구어체 질문은 M3에서 정답 별첨이 7위 → 3위로 올랐다. 그러나 평가셋 전체로는 구어체가 나빠졌다.

### 해석

1. **구어체가 크게 좋아졌다.** Hit@4 0.71 → 0.86~1.00, MRR 0.63 → 0.79~0.82. v0부터 못 찾던 Q43이 두 번 모두 1위다. D7을 발견한 구어체 질문도 정답 별첨이 7위 → 3위로 올라 LLM에 전달된다.
2. **전체 Hit@4는 차이가 없다** (0.96 → 0.93 / 0.96). 1등 정확도(Hit@1 +0.04~0.07, MRR +0.02~0.04)는 올랐지만, 4위 안에 드는 비율은 얻은 만큼 잃었다.
3. **조건 판단과 여러 조항이 나빠졌다.** Q21·Q25는 두 번 모두 4위 밖으로 밀렸다. 여러 조항 Recall@4는 0.73 → 0.60~0.64다. 질문을 검색어 한 줄로 줄이면서 조건이나 둘째 주제가 빠진 것으로 보인다 (추정, CSV의 검색어 열로 본인 확인 필요).
4. **실행마다 1~2문항이 달라진다.** 같은 설정에서 Q05·Q41의 순위가 달랐다. LLM이 끼는 실험은 한 번 실행으로 판단하지 않는다.
5. **기본값으로 켜지 않는다.** `--rewrite` 옵션으로만 둔다. 구어체 개선은 분명하지만, 실험 규칙의 1순위 지표(Hit@4)가 오르지 않았고 조건 판단 하락이 두 번 모두 재현됐다.

2. **원래 질문 점수가 조건 판단을 지켰다.** M4에서 밀린 Q21·Q23·Q25가 v1 순위로 돌아왔다. 게다가 다듬은 검색어 덕분에 Q22·Q26·Q27이 1위로 올라 조건 판단 MRR이 0.62 → 0.82가 됐다.
3. **구어체 이득은 대부분 남았다.** Q40·Q43이 1위다.
4. **남은 약점: 다듬은 검색어 쪽 유사도가 전반적으로 높다.** 정답 있는 질문의 1등 유사도 평균이 0.682 → 0.711로 올랐다. 다듬은 검색어가 엉뚱한 청크에 준 높은 점수가 원래 질문의 정답 점수를 덮는 경우가 있다 (Q35·Q39, 여러 조항 MRR 0.94 → 0.84~0.85).
5. **크기는 규칙 기준보다 작다.** Hit@4 +0.02~0.04로 0.05에 못 미친다. 다만 v1이 이미 45문항 중 43개(0.96)라 오를 수 있는 폭이 최대 0.04였다. Hit@1·MRR·유형별 변화와 보류셋으로 판단을 보충한다.
6. **유사도로 미리 거절하는 기준은 여전히 정할 수 없다.** 정답 있는 질문의 최소(0.610 / 0.616)가 규정에 없는 질문의 최대(0.628)보다 낮다.
7. **판단: 채택 후보.** 보류셋에서 v1보다 나빠지지 않으면 챗봇 기본값으로 켠다.

D7을 발견한 구어체 질문은 M4b에서도 정답 별첨이 3위다 (점수는 다듬은 검색어 쪽).

### 보류셋 확인 (미완료)

- v1과 M4b로 보류셋을 실행했지만 20문항이 모두 `[제외]`됐다. 정답 칸이 모두 `확인필요`이고 기대 답 칸은 비어 있다. 보류셋 정답을 아직 채우지 않은 상태다.
- 채점할 문항이 0개라 검색어 다듬기 API 호출은 일어나지 않았다.
- D7(별첨 분리)로 본문이 바뀐 조문은 지침 1개 문서의 부칙1뿐이고, 평가셋·보류셋 정답에 쓰이지 않았다. 보류셋을 채울 때 분할 변경을 따로 반영할 필요는 없다.
- 현재 지문은 `beb17001b35b`(미완성)다. 정답을 채운 뒤 새 지문을 적고, 그 뒤로는 고치지 않는다.
- 결과 CSV 이름에 평가셋 이름을 넣었다 (`retrieval-holdout_set-…`). 튜닝 중에 보류셋 결과를 열지 않기 위해서다.

### 결정

- 사용자 결정으로 **평가셋 결과만으로 M4b를 채택**해 챗봇 기본값으로 켰다. 실험 규칙(보류셋 확인 후 채택)의 예외다.
- 보류셋 정답을 채우면 v1과 M4b를 다시 잰다. M4b가 v1보다 나쁘면 되돌린다 (`chat.py --no-rewrite`).
- `scripts/chat.py`는 검색어 다듬기와 원래 질문 합치기가 기본이고, `--no-rewrite`로 끈다.
- `search.py`·`eval_retrieval.py`는 기본이 v1 그대로다. 외부 전송이 없고 결과가 실행마다 같아야 실험 도구로 쓸 수 있기 때문이다. 챗봇과 같은 검색을 보려면 `--rewrite --merge-original`을 붙인다.
- 다듬기 모델은 `REWRITE_MODEL`이 비어 있으면 Claude는 `claude-haiku-5-5`(평가에 쓴 모델), OpenAI는 답변 모델을 쓴다.
- 늘어나는 비용: 질문마다 다듬기 API 호출 1회(질문만 전송, 약 1초)와 임베딩 검색 1회.
